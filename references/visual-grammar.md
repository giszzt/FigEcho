# Visual Fingerprint Extraction

目标不是罗列审美形容词，而是找出少量、高辨识度、可迁移的组合规则。最终风格相似度由这些规则共同决定。

## 观察顺序

每条结论按四步写：

1. observation：画面里直接可见的事实；
2. function：它如何组织信息或形成辨识度；
3. transfer_rule：换成新内容后怎样继续成立；
4. evidence：参考图中的区域或跨图重复证据。

没有像素分析时只写近似比例、明度区间或相对关系，不伪造精确测量。

先做整图观察，再做局部观察。整图观察确定主轴、分区比例、视觉重心、阅读节奏和信息密度；局部观察确定容器、线条、字体、图标和表面细节。不得从一个醒目的颜色或单个图标直接概括整张图的风格。

## 辨识度校准

每个候选锚点都回答三个问题：

1. 去掉它后，画面是否会明显滑向常见技术图模板；
2. 它是否与至少一个其他维度形成稳定组合，例如“三级容器 + 紧凑网格”或“线稿图标 + 黑色直角箭头”；
3. 它能否在不复制源内容和精确构图的前提下迁移到新主题。

只有三个问题都能给出具体答案的特征才进入高权重锚点。单独的色值、圆角、阴影或“扁平化”通常只是辅助参数。

对布局、组件、连接线和字体至少记录一个相对量：例如分区宽度比例、容器层级、圆角相对卡片高度、线宽相对描边、标题与正文的字号比、图标与文字的面积比。没有像素测量时使用可观察的区间，不伪造精确值。

## 八个维度

### 1. Layout

- 图型原型：流程、分层架构、包含、双轨、矩阵、中心辐射、反馈循环、时间轴、多面板或混合型；
- 画布比例、安全边距、主轴、视觉重心、阅读路径；
- 宏观分区的数量与比例，外层分区与内部网格的关系；
- 重复模块的尺度、节奏、对齐、间距、留白与最大嵌套深度；
- 哪些布局来自内容数量，哪些是稳定的风格习惯。

### 2. Components

- 容器形状、圆角、填充、描边、标题条、编号徽章、标签和注释；
- “图标 + 标题 + 说明”“公式 + 解释”“图表 + 结论”等固定搭配；
- 组件内部 padding、标题与正文的位置关系、层级深度。

### 3. Connectors

- 直线、折线或曲线；实线、虚线或点划线；
- 箭头形态、粗细、颜色、端点位置和跨区路由；
- 不同线型分别表达顺序、反馈、映射、包含还是装饰。

### 4. Palette

- 背景、结构、文字、线条和强调色槽位的颜色角色；
- 近似色值、色相范围、饱和度、明度、对比度和面积分布；
- 颜色是语义编码、分区编码还是纯表面特征。

色值与业务语义必须分开记录。背景、文字和描边通常可以作为稳定角色；彩色强调使用 Accent A / B / C 等中性槽位记录，transfer_rule 明确按新内容层级或分组重新映射。源图中的“红色=治理、蓝色=底座”等只属于当次内容映射，除非多张跨主题参考图证明该语义关系稳定，否则不能进入通用风格规则。

### 5. Typography

- 字体类别和可替代字体，不猜品牌字体；
- 总标题、分区标题、节点、正文、注释和公式的字号比例、字重、行高、对齐；
- 字形是几何、学术、工程、编辑、手写还是教育型；
- 文本与容器、图标或色块的绑定方式。

### 6. Iconography

- 线性、面性、扁平、手绘、拟物、3D、照片或混合；
- 轮廓粗细、视角、色彩数量、细节等级和人物表现；
- 图标是否统一置于徽章、卡片、底座或特定位置。

Logo、专有角色和人物身份不是风格，进入源内容排除项。

图标的题材与画法分开记录。数据库、地图、芯片、矿石、海浪等对象名称属于内容；线性或面性、轮廓粗细、视角、色彩数量、细节等级、底座形式和图文比例才属于可迁移风格。transfer_rule 必须说明“从新内容派生题材，再用该图标语言绘制”，不能保存源图对象清单。

### 7. Surface

- 背景纸张、颗粒、阴影、描边抖动、渐变、发光、网点、玻璃或 3D 材质；
- 平面深度由描边、叠层、阴影还是颜色对比产生；
- 装饰纹理占多大权重。

表面特征默认是风格偏好，不自动升级为通用硬禁令。参考图没有 3D、渐变或阴影，只能支持“默认采用平面处理”；当用户明确提供照片、Logo、外部插图或要求另一种媒介表现时，允许作为条件分支，并用该风格的边框、色调、尺度和层级进行整合。

### 8. Density

- 每个主区的节点数、文字行数、图文占比和局部留白；
- 高密度靠紧凑网格、层级压缩还是小字号实现；
- 视觉节奏是均匀重复、主次错落还是局部聚焦。

## Signature Anchors

从八个维度中选 5–7 个风格锚点，至少覆盖四个维度，权重总和为 100。锚点必须是组合规则，不是单词。每个锚点包含 id、dimension、rule、evidence、weight、confidence 和 prompt_token。

示例：

    id: nested-pastel-panels
    dimension: components
    rule: 浅灰标题条、虚线外框、马卡龙内卡组成三级容器
    evidence: reference-1 的全部宏观面板
    weight: 24
    confidence: high
    prompt_token: three-level containers with pale gray header bars, rounded dashed macro frames and pastel inner cards

坏锚点：“科技感”“蓝色”“扁平化”。它们没有结构、比例或功能关系，任何模板都能命中。

锚点要优先选择：

- 在画面上占面积大或反复出现；
- 同时影响多个组件；
- 与常见模板有明显差异；
- 换主题后仍能成立；
- 能被生成模型用一句具体指令复现。

完成单个锚点后，再写一条“组合指纹”：说明最高权重的 3–4 个锚点如何共同出现、彼此制约以及分别落在画面的什么层级。style_summary 与【关键风格特征】必须保留这种组合关系，不能把锚点拆成互不关联的清单。

prompt_token 不是关键词标签，而是一条可执行规则。它至少包含形态、相对关系和使用位置中的两项；例如“外层浅灰虚线圆角框包住紧凑内卡，标题条贴附于框体上沿”，而不是“浅灰圆角框”。

## Anti-generic

记录最容易把该风格压扁成普通模板的替代做法，并给正向目标。例如：

- 不要把三级容器压成同一种卡片；保留宏观框、标题条和内卡的层级差；
- 不要只复用马卡龙配色；同时复用紧凑网格、黑色折线箭头和教育型线稿图标；
- 不要机械复制参考图的三栏；按新内容拓扑重算分区，但保留对齐节奏与容器语法。

## 单图与多图

- 单图：generalization = single-reference-hypothesis；作者级风格置信度不高于 medium，但局部可观察锚点可以是 high。
- 多图：先各自抽取，再取功能一致的交集；只出现一次或相互冲突的特征进入 conditional_rules，不塞进锚点。

## 源内容边界

source_exclusions 保存原图文字、Logo、数据、人物身份、版权标记、水印、独特角色与专有图表。可自动扫描的专有词使用 literal:<term>。

这些排除项只进入 style-spec.json、分析报告和 generate Prompt。extract 的通用风格 Prompt 不谈源图，也不复述这些专有词。

## Transfer Boundary

style-spec.json 的 transfer_boundary 固定记录四项适配策略：布局按新内容拓扑重算、图标题材从新内容派生、强调色语义按新内容层级分配、用户提供或内容必需的素材允许作为 supporting insert。hard_constraints 只保存跨主题仍成立的准确性与可读性规则；style_defaults 保存参考图支持的视觉偏好。
