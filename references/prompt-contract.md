# Prompt Contract

提示词是用户可直接使用的成品，不是视觉分析摘要。默认使用中文分模块结构；用户明确要求其他语言时，再使用对应语言。

## 三层边界

一份可迁移模板必须把信息分成三层，不能相互混写：

- **风格不变量**：容器、线条、字体、色值、表面处理、相对比例、对齐节奏等可观察视觉语法。
- **内容适配规则**：布局按新内容拓扑重算；图标题材从新内容的实体、对象与动作中选择；强调色按新内容层级重新分配；用户提供或内容必需的素材可作为 supporting insert。
- **本次生成约束**：只存在于 prompt.md，包括具体节点、关系、文字、图标题材、色彩语义映射、插入素材与源内容排除项。

style-prompt.md 只包含前两层。prompt.md 在完整保留前两层的基础上加入第三层。

## 统一提示词模板

style-prompt.md 与成图用 prompt.md 都使用以下结构。没有某类元素时也保留模块，明确写出适合该风格的处理方式。

【图像类型】

说明画布方向、技术图类别、目标使用场景和整体清晰度要求。

【内容结构】

提供可直接替换的内容槽位，并说明怎样按内容关系组织：

1. [主模块一]：[核心内容与关系]
2. [主模块二]：[核心内容与关系]
3. [主模块三]：[核心内容与关系]

主模块数量写成适配范围，不机械锁定参考图的栏数。

同时写出文字负载预算：每个主区最多几个短标签、单个标签最多几个字、说明文字出现在哪一层。位图模型的文字能力有限，没有预算的模块最终会被塞满并糊掉。成图用 prompt.md 必须写出具体数字，来自 visual-plan 的 density_budget；通用模板写可适配范围即可。

【整体版式】

写清画布比例、宏观分区、阅读方向、视觉重心、网格、边距、留白、嵌套层级和信息密度。

【组件语言】

写清容器形状、圆角、描边、填充、标题条、编号、徽章、局部卡片和内边距的组合规则。

【连接线】

写清线型、箭头、粗细、颜色、端点、路由、分支、汇聚、反馈和避免交叉的方法。

【插图与图标风格】

写清图标类型、轮廓、视角、细节等级、人物表现、图标与文字的搭配，以及不需要插图时的几何处理。通用模板只规定图标怎样画，不列举数据库、地图、矿石、海浪、盾牌等具体题材；具体图标题材必须从新内容的实体、对象和动作中派生。

【配色】

写出颜色角色、具体 #RRGGBB 色值、面积比例、明度、饱和度、对比关系和强调色使用条件。至少提供背景、结构、文字/线条或强调中的三个不同色值。背景、文字、描边等稳定角色可以固定；彩色强调使用“强调色 A / B / C”等中性槽位，按新内容的层级、分组或关系重新映射，不能固化为“酒红=治理、橙色=能力、蓝色=底座”等单一业务语义。即使参考图是单色或灰度，也要给出背景、正文和层级灰的具体编码。

【字体层级】

写清标题、分区、模块、节点、正文、注释的字体类别、字号比例、字重、行高和对齐方式。

【视觉气质】

用一段完整描述总结图的学术感、工程感、教育感、编辑感或其他视觉性格，并说明应避免滑向哪类常见模板。

【关键风格特征】

列出 5–7 条最能决定视觉家族的组合特征。它们必须覆盖至少四个维度，并与 style-spec.json 的风格锚点一致。

【生成约束】

分三类列出约束：

- 硬约束：内容准确、关系拓扑正确、不编造、无源内容泄漏、文字清晰、无裁切与遮挡；
- 风格默认：根据提取到的视觉语法，默认采用或避免某种表面处理；
- 条件规则：用户提供或内容必需的 Logo、照片、外部插图可插入并统一边框、色调和尺度；3D、渐变、发光、玻璃、阴影等是否采用，以参考图证据和本次需求为准。

不得把 Logo、照片、3D、渐变、发光、玻璃、阴影或写实插画写成跨所有任务生效的绝对禁令。

## 编写要求

- 把每个 signature anchor 的 prompt_token 自然写入对应模块，而不是集中堆在一段 Visual DNA 中。
- 将 visual_system 八个维度中的 transfer_rules 全部写入对应模块；高权重锚点负责辨识度，完整迁移规则负责防止字体、表面、密度等次级特征在成图时丢失。
- 使用肯定、具体、可执行的中文制图语言。
- 将稳定风格写成规则，将新内容写成占位符，将内容条件特征写成可适配范围。
- 【整体版式】必须明确按新内容拓扑重算分区数量、比例和阅读路径；不得把某一张参考图的左中右业务结构固化为通用模板。
- 【插图与图标风格】只保存表现形式，不保存具体题材清单；题材由新内容动态决定。
- 【配色】保留具体色值与面积关系，用中性强调槽位描述可迁移色彩系统，并明确按新内容层级重新分配语义。
- 配色、字体、容器、线条和图标应给出足够细节，使提示词单独复制后仍能重建完整视觉语言。
- 每个模块都必须形成可执行约束组：图像类型包含方向、类别和使用场景；内容结构包含节点与关系；整体版式包含比例、阅读路径、网格、边距/留白和密度；组件包含形状、描边、填充和内边距；连接线包含线型、箭头、粗细、颜色和路由；图标包含家族、轮廓、视角和细节；配色包含语义角色与具体编码；字体包含主标题、模块标题、正文、字体类别和层级参数；视觉气质包含正向目标与反模板边界；生成约束覆盖文字、关系、裁切和无语义装饰。
- 【关键风格特征】列出 5–7 条编号特征，不能少于 signature anchors 的辨识度覆盖。
- 不依赖“参考图、原图、这张图、Image 1、style reference、source image、supplied image”等当前语境。
- 不包含源图标题、品牌、人物、数据、模块名称、版权信息或 source_exclusions 中的 literal 专有词。

## 交付规则

prompt-only：

- 最终回答直接粘贴完整提示词，使用单个代码块便于复制。
- 不附风格分析、JSON、验证结果、质量报告或内部文件链接。

analysis-and-prompt：

- 提供简洁分析和完整提示词。
- 结构化文件只在用户明确需要时提供。

## Generate Prompt

用于直接生成图片的 prompt.md 不是另一种提示词格式。它以 style-prompt.md 为母版，保持同样的十一模块结构和风格规则，再完成以下替换：

1. 将【内容结构】中的占位符替换为 content-graph 的主节点、必要关系和逐字文字；
2. 将 visual-plan 的图型、分区、阅读路径、视觉重心、密度预算和锚点落位写入对应模块；
3. 在十一模块之前增加一段简短的“输入图片角色”，明确每张图片是风格参考、编辑目标还是插入素材；
4. 在【生成约束】中加入源内容排除项、禁止编造项和本次内容边界。
5. 在【插图与图标风格】中填入从本次内容派生的具体图标题材；在【配色】中把中性强调色槽位映射到本次内容角色；有 supporting insert 时记录其素材角色和融合方式。

prompt.md 必须包含全部十一模块、全部 signature anchor 的 prompt_token、全部 required 节点与关系、全部 required exact text，以及 visual-plan 选择的图型。不要增加“新图主题”模块，也不要把完整模板压缩成英文摘要、Visual DNA 列表或散文式说明。

最终交付：抽取任务交付 style-prompt.md；成图任务交付实际使用的 prompt.md。两者都必须是可复制的完整提示词。

通过 Style Library 复用时，模板 style-prompt.md 仍是母版；Style Pack 中保存的原始参考图作为真实 style reference 与 prompt.md 同时进入生成调用。
